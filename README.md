# Steve's Coffee | Order Ahead & Rewards Pilot

The customer rewards screen is at `/` and the staff dashboard is at `/staff`.

## Loyalty-only pilot

Online ordering is on hold by default. Members join with a phone number or email and a password, starting at zero points. Existing phone accounts can sign in with their current PIN. Staff look up the identifier the member used to join, then record a unique receipt reference and the subtotal after discounts and before tax. Each purchase earns one point per full $5. For example, $12.50 earns two points. If multiple registers use the same receipt numbers, include a register or location prefix. Retrying the same receipt, member, and amount does not award points twice.

The pilot uses its own points ledger. Point collection is active in the pilot. Checkout and reward redemption are paused. Existing orders can still be handled on the staff dashboard. Set `ORDERING_ENABLED=1` to restore online ordering. On the Free Render setup, a restart or redeploy can clear the temporary database, including receipt credits. See [DEPLOY.md](DEPLOY.md) for the original Render setup and order test walkthrough.

## Run locally

Python 3.10 or later. There are no packages to install.

```bash
PILOT_CODE=local-test-access-code STAFF_PIN=local-staff-test-code ALWAYS_OPEN=1 TZ=America/Los_Angeles python3 server.py
```

Open http://localhost:8000 and use the local access code above. Use sample customer information. For the staff screen, also enter the separate local staff code. Use unique generated codes on Render.

## When online ordering is enabled

Customers can create a test rewards account, order ahead for counter pickup, track the order, and see their points and reward activity. Staff uses the app's order screen to prepare orders and confirm pickups. Orders earn one point per full $5 after discounts and before tax once staff marks the order picked up. Sample rewards are a free drink for 100 points and a free bag of beans for 200 points. Cancellation returns points used on the order.

The sample menu lives in `menu.json`. Rewards and earning rules are in `server.py`. The pilot uses a password with an unverified phone or email identifier. It does not send verification messages or provide password recovery. Orders use simulated Clover and are pay at pickup. The SQLite ledger tracks points for app orders and staff-entered purchases.

## Settings

| Variable | Default locally | Purpose |
| --- | --- | --- |
| `PILOT_CODE` | Unset | Shared tester access code, generated by the Blueprint for Render |
| `STAFF_PIN` | Unset | Staff access code, generated separately by the Blueprint |
| `DB_PATH` | `steves.db` beside the server | SQLite file. Blueprint uses `/data/steves.db` on the disk |
| `PORT` | `8000` | HTTP listen port, supplied by Render when hosted |
| `TZ` | System time zone | Blueprint uses `America/Los_Angeles` |
| `STORE_OPEN` / `STORE_CLOSE` | `06:30` / `18:00` | Sample pickup hours, in the configured time zone |
| `ALWAYS_OPEN` | `0` | Set to `1` during staff testing to ignore sample hours |
| `PREP_MINUTES` | `10` | Minimum preparation time |
| `SLOT_CAPACITY` | `5` | Max active orders per five-minute slot |
| `CURBSIDE_ENABLED` | `0` | Set to `1` to try curbside check-in |

The Render pilot uses a single service with simulated Clover and generated credentials. Changing the pilot code invalidates previously issued pilot access cookies.
